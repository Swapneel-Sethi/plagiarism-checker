# Plagiarism Checker

**Originality analysis with a visible trail.**

A browser-first plagiarism and AI-writing checker. It combines word-level shingle matching, a live web search layer, an optional semantic paraphrase pass and an eight-parameter stylometric index.

[Local app](#run-it) · [Detection engine](assets/engine.js) · [Serverless API](api/analyze.js)

## Problem

Most free plagiarism checkers hide the evidence behind a single percentage. Most AI detectors present a score without explaining which stylistic features produced it. Both are hard to audit and easy to misinterpret.

This project exposes the matching passages, the source documents and the individual stylometric parameters behind the result.

## Solution

- **Plagiarism:** split the document into 5-word shingles and measure containment against each reference source: `matched_shingles / doc_shingles × 100`. Matched passages are highlighted in the Document Map.
- **Web scan:** search distinctive sentences, fetch top results, extract page text, and run the same containment logic. Web matches appear in the same report as local matches.
- **Semantic pass:** optionally embed sentences and source passages with Gemini embeddings to catch heavy paraphrase that lexical matching misses.
- **AI-writing index:** score eight stylometric parameters and average them into one index.
- **Corpus management:** add reference documents at runtime; they persist in local storage.

### AI-writing parameters

1. Burstiness (sentence-length variance)
2. Rare-word ratio
3. Function-word density
4. Hedge / boilerplate phrases
5. Repeated 4-gram ratio
6. Type-token ratio
7. Average word length
8. Comma density

## Proof

- **Deterministic core.** The offline engine is plain JavaScript and runs without a model or network call.
- **Evidence-first report.** Every source lists its overlap percentage; matched passages are highlighted.
- **Degradation is explicit.** If the web search or semantic layer times out or runs out of quota, the report still returns the offline result and says what was unavailable.
- **Test harness included.** `accuracy_run.js` runs labelled samples, `e2e_tests.js` exercises the server, and `verify_keys.js` checks provider configuration.
- **No build step.** The app is static HTML/CSS/JS plus serverless functions.

This is a heuristic engine, not a certified detector. The project does not claim a benchmark accuracy.

## How it works

```text
document
  → 5-word shingles
  → containment against local corpus
  → optional web search + page extraction
  → optional Gemini embedding similarity
  → merged report
  → highlighted document + source list + AI-style index
```

The local development server (`server.js`) serves the site and the API on the same origin. On Vercel, `api/analyze.js` and `api/web-sources.js` provide the same paths as serverless functions.

## Technology

- Vanilla JavaScript, HTML, CSS
- Node.js HTTP server for local development
- Vercel serverless functions
- SerpAPI / DuckDuckGo fallback for web search
- Gemini embeddings for the optional semantic pass
- Local storage for the corpus

## Demo

There is no stable public deployment URL in this repository. The Vercel preview deployments are access-protected.

Run it locally:

```bash
node server.js
```

Open http://localhost:3000.

To enable web scanning, provide a SerpAPI key in the page, pass it as `node server.js YOUR_KEY`, or set `SERPAPI_KEY` in `.env`. Without a key, search falls back to DuckDuckGo/Bing and may be rate-limited.

## Run it

Static mode:

```bash
python3 -m http.server 8000
```

Open http://localhost:8000. Web scanning is unavailable in this mode.

Full mode:

```bash
node server.js
```

Deploy to Vercel:

```bash
npx vercel --prod
```

Set `SERPAPI_KEY` and optionally `GEMINI_API_KEY` as environment variables. Do not commit keys.

## Limitations

- The offline engine matches identical or near-identical words. It does not understand meaning; the optional semantic pass narrows that gap but is best-effort.
- Web scanning only covers what the search provider indexes and can fetch.
- Scanned/image-only PDFs have no extractable text and need OCR first.
- The AI-writing index is a stylistic estimate, not proof that a document was generated by AI.
- Very long documents can hit serverless time limits; the API returns the offline result rather than failing the whole request.
- Local corpus data lives in browser storage and is not shared across devices.
